# JavaScript: ловушки в правильном алгоритме

Цель: не потерять данные из-за сравнения, мутации, проверки пустоты или преобразования типов. Для человека с Python-бэкграундом особенно важны ссылки, truthiness пустых коллекций и числовая сортировка.

## 1. Ссылки и поверхностные копии

```ts
const a = { id: "A" };
const b = { id: "A" };
const c = a;
a === b; // false
a === c; // true
new Set([a, b]).size; // 2
```

Объекты и массивы сравниваются по идентичности, не по содержимому. Это ближе к Python `is`, чем к сравнению словарей через `==`. `includes({ id: "A" })` не найдёт другой объект с таким же полем. Ищи по `id` или строй индекс.

`const` запрещает переназначение переменной, но не изменение объекта. Spread делает новый внешний контейнер; вложенные объекты остаются общими.

```ts
const source = { id: "A", address: { city: "Austin" }, tags: ["new"] };
const copy = { ...source };
copy.id = "B";                // source.id остаётся A
copy.address.city = "Denver"; // меняется и source.address
copy.tags.push("featured");   // меняется и source.tags

const updated = {
  ...source,
  address: { ...source.address, city: "Boston" },
  tags: [...source.tags, "verified"],
};
```

Копируй контейнеры на пути к изменяемым полям. Полная глубокая копия ради одного поля обычно лишняя. Порядок spread имеет значение: последнее присваивание поля побеждает. `{ ...source, id: "X" }` заменяет ID; `{ id: "X", ...source }` возвращает исходный ID.

## 2. Массивы и сортировка

```ts
[100, 20, 3].sort();               // [100, 20, 3], сравнение как строк
[100, 20, 3].sort((a, b) => a - b); // [3, 20, 100]
```

Компаратор возвращает отрицательное число, ноль или положительное. `a > b` возвращает boolean и не является правильным компаратором. Для второго критерия сравни сначала первый и только при равенстве переходи ко второму.

`sort` и `reverse` меняют исходный массив и возвращают его же. `push` возвращает новую длину; `pop` — удалённый элемент. `slice(start, end)` возвращает копию диапазона, не включая end; `splice(start, count)` меняет исходный массив и возвращает удалённые элементы.

```ts
const sorted = [...items].sort(compare);
// В среде с поддержкой ES2023:
const alsoSorted = items.toSorted(compare);
```

`filter` и `map` создают внешний массив, но callback всё ещё может мутировать исходные объекты. Цепочка `items.filter(predicate).sort(compare)` сортирует новый массив и не меняет порядок items. Для одного совпадения используй `find`; для проверки существования — `some`; `filter` собирает все совпадения.

## 3. Отсутствующие значения

Falsy: `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`. Пустые массивы и объекты — truthy, в отличие от Python. Для непустого массива проверяй `length`, не сам массив.

```ts
0 || 3;         // 3
0 ?? 3;         // 0
"" ?? "name";   // ""
null ?? 3;      // 3
const { price = 100 } = { price: null }; // null
```

`||` заменяет все falsy. `??` заменяет только null/undefined. Значение по умолчанию при деструктуризации срабатывает только на undefined.

В PATCH-контракте `{}` может означать «не менять», `{price: null}` — «удалить», а `{price: 0}` — «установить ноль». Тогда `patch.price ?? oldPrice` ошибочно проигнорирует удаление. Нужна проверка именно undefined:

```ts
const nextPrice = patch.price === undefined ? oldPrice : patch.price;
```

`obj.address?.city` защищает от null/undefined в address, но не проверяет тип внешних данных. `filter(Boolean)` удаляет и нули, и пустые строки; для удаления только отсутствующих значений сравни с null и undefined явно.

## 4. Числа и даты

```ts
Number(" ");          // 0
Number(null);         // 0
Number("500usd");     // NaN
parseInt("500usd", 10); // 500
parseInt("12.9", 10); // 12
```

Преобразование не равно валидации. Сначала проверь тип и пустоту, затем преобразуй, затем проверь конечность и бизнес-ограничения. `parseInt` читает допустимое начало, поэтому не годится как строгая проверка целого поля.

```ts
function parsePrice(value: unknown): number {
  if (typeof value !== "number" && typeof value !== "string") {
    throw new Error("Expected number or string");
  }
  if (typeof value === "string" && value.trim() === "") {
    throw new Error("Empty price");
  }
  const price = Number(value);
  if (!Number.isFinite(price) || price < 0) throw new Error("Invalid price");
  return price;
}
```

Такой контракт допускает числовые строки вроде `"1e3"`. Если нужен только десятичный формат, проверяй формат отдельно. `typeof NaN` — `"number"`, `NaN === NaN` — false. Используй `Number.isNaN`, а чтобы отвергнуть ещё и Infinity — `Number.isFinite`. Эти методы не преобразуют строки.

`0.1 + 0.2 !== 0.3`: двоичная арифметика имеет ограниченную точность. Для денег используй минимальные целые единицы в безопасном диапазоне или decimal-арифметику. Идентификаторы оставляй строками: ведущие нули и длинные числа могут потеряться при преобразовании.

`Date.parse` возвращает миллисекунды или NaN. Внешние Unix timestamps часто в секундах: единицы укажи в имени. Для событий предпочитай формат с явной зоной, например `2026-10-01T12:00:00Z`. Строка даты-времени без зоны интерпретируется как локальное время. Парсинг не заменяет строгую проверку формата API.

```ts
const a = Date.parse("2026-10-01T10:00:00+02:00"); // 08:00 UTC
const b = Date.parse("2026-10-01T09:00:00Z");      // 09:00 UTC
a < b; // true
```

Не сравнивай произвольные ISO-строки лексикографически: при разных смещениях это не хронология. Нормализуй время один раз на входе.

## Практика

```ts
const source: Array<{ id: string; tags: string[] }> = [
  { id: "A", tags: [] }, { id: "B", tags: [] },
];
const result = source.map(x => ({ ...x }));
const first = result[0];
if (first === undefined) throw new Error("Expected a first element");
first.id = "X";
first.tags.push("new");
result.reverse();
const retries = 0 || 3;
```

Что изменилось в source? Чему равен retries?

### Спойлер

Порядок source остался A, B и ID не изменился. Теги A стали `["new"]`: вложенный массив общий. retries равен 3; для сохранения явного нуля нужен `??`.
